# 飞书私聊调用 Codex：设计说明

## 目标

用户不在电脑旁时，可通过飞书私聊机器人查看本机 Codex 的进行中任务，指定其中一个任务继续工作，并在飞书中收到进度与最终结果。

## 使用方式

用户向机器人私聊发送以下指令：

- `列出任务`：返回当前可继续的 Codex 任务，含序号、标题和项目路径。
- `继续 2：修复登录报错`：将任务描述发送给编号 2 的 Codex 任务。
- `状态 2`：返回该任务是否正在执行及最近进展。
- `停止 2`：请求停止该任务。

机器人依次回复“已接收”“执行中”和最终结果。出错时说明失败原因及下一步操作。

## 架构

使用飞书官方 Node SDK 的 WebSocket 长连接接收消息，不使用公网回调地址。运行在本机的桥接服务包含四个独立模块：

1. **飞书连接器**：接收私聊消息、向同一会话发送文本回复，并在掉线后重连。
2. **身份守卫**：首次配对时将发送人的飞书 `open_id` 绑定为唯一允许的用户；忽略所有群消息和其他用户的私聊消息。
3. **任务路由器**：调用本机 `codex agents` 获取当前任务；将用户选择的序号映射为精确任务 ID。
4. **Codex 执行器**：将新指令续接到被选中的任务，采集状态和最终输出，并回传到飞书。

配置文件只保存在本机，包含飞书应用凭证、已绑定用户的 `open_id` 和必要的运行状态。它不会提交到 GitHub。

## 安全边界

- 仅处理已绑定用户的私聊文本指令。
- 初次绑定使用本机生成的一次性配对口令，防止其他人抢先绑定机器人。
- 不处理群聊、文件、链接自动指令或来自其他用户的消息。
- Codex 以工作区写入权限运行；涉及删除大量文件、对外发送内容、变更云端权限、提交密钥或线上部署时，桥接服务先在飞书请求明确确认。
- 应用密钥、SSH 私钥和个人令牌均不写入日志、不回传飞书、不提交 Git。

## 可靠性与限制

- Mac 必须开机、联网且桥接服务正在运行；合盖、断网或关机期间不能执行任务。
- 飞书断线时服务会自动重连；Codex 任务运行失败、超时或不可用时会回传清晰错误。
- 首版仅支持文本私聊与文本结果；图片、文件、卡片消息和多人协作不在范围内。
- 任务输出过长时，机器人发送摘要，并提示用户查看本机完整记录。

## 验收标准

1. 已绑定用户发送 `列出任务` 后，能收到当前任务列表。
2. 已绑定用户发送 `继续 N：...` 后，指定 Codex 任务收到指令并产出结果。
3. 最终结果或失败信息能回传到原飞书私聊。
4. 群消息、未绑定用户消息和错误指令均不会触发 Codex 执行。
5. 飞书应用凭证和本地密钥不出现在 Git 历史或飞书消息中。
